# 词库系统（Lexicon System）

> 目标：提供一个比知识库更轻量的“词:含义”解释系统，支持**常加载**与**懒加载**两类词条源，便于在对话中快速释义网络用语、缩写、口语等。
> **该系统的主要方向是口语，缩写等轻量词汇。并不是类似知识库那样的大型系统**

## 1. 设计目标

- **轻量**：仅处理短文本词条（`词: 含义`），不做向量检索与复杂召回。
- **可维护**：词库文件可直接人工编辑，格式简单。
- **分层加载**：
  - 常加载：高频词条（网络用语、缩写、口语）启动即加载。
  - 懒加载：低频词条按需加载，降低启动与常驻内存开销。
- **可扩展**：可按主题拆分文件，不影响主逻辑。

## 2. 目录结构

```text
lexicon/
├─ __init__.py
├─ manager.py                # 词库加载与检索逻辑
├─ always/                   # 常加载词库目录
│  ├─ internet_slang.dict
│  ├─ abbreviations.dict
│  └─ colloquial.dict
└─ lazy/                     # 懒加载词库目录
   ├─ game_terms.dict
   └─ finance_terms.dict
```

## 3. 数据格式（词:含义）

词库文件使用 `.dict` 扩展名，UTF-8 编码，每行一个词条：

```text
摸鱼: 在工作或学习期间做与任务无关的事
YYDS: 永远的神，表示非常厉害
ROI: 投资回报率（Return on Investment）
```

### 3.1 语法规则

- 空行忽略。
- 以 `#` 开头行为注释。
- 使用**首个**英文冒号 `:` 作为分隔符。
- 分隔符左侧为关键词（`term`），右侧为含义（`meaning`）。
- 若一行没有 `:`，视为非法行并跳过。

## 4. 加载模型

### 4.1 常加载（Always Loaded）

- `LexiconManager` 初始化时扫描 `lexicon/always/*.dict`。
- 将词条解析并合并到内存索引 `always_terms`。
- 同词冲突：后加载文件覆盖先加载文件（便于覆盖修订）。

### 4.2 懒加载（Lazy Loaded）

- 初始化时扫描 `lexicon/lazy/*.dict` 并提取所有关键词，生成 `manifest(term -> file)`。
- 查询时不再全量遍历懒文件，而是通过 manifest 直接定位目标词条所在文件。
- 仅在命中时加载对应懒文件并缓存，后续同文件词条命中不再重复读取文件。

## 5. 运行时 API（建议）

`lexicon/manager.py` 提供 `LexiconManager`：

- `get(term: str) -> str | None`
  - 精确查询关键词含义。
  - 查询顺序：常加载 -> 已加载懒词库 -> 逐文件懒加载。
- `search(keyword: str, limit: int = 10) -> list[tuple[str, str]]`
  - 模糊检索（term 或 meaning 包含关键字）。
  - 优先搜索当前已加载词条，不强制一次性加载全部懒词库。
- `supplement_meanings_for_text(text: str, limit: int = 10) -> list[tuple[str, str]]`
  - 每次用户输入时仅匹配懒加载 `manifest` 关键词。
  - 某个词命中后，仅返回该词对应的含义（以 `[(词, 含义)]` 结构输出）。
- `stats() -> dict`
  - 返回词条数量、懒加载命中次数、已加载懒文件数等统计。

## 6. 边界与异常处理

- 目录不存在：按空词库处理，不抛异常。
- 文件编码异常：跳过该文件并记录 warning。
- 非法行：跳过并记录 debug（避免污染主流程）。
- 重复词条：后写覆盖前写，保持确定性。

## 7. 与知识库（RAG）的关系

- 词库系统不替代 `memory/rag.py`。
- 词库适用于“短定义查询”（低成本、低延迟）。
- RAG 适用于“长文本知识召回”（高语义能力）。

建议路由：
- 用户问“某词是什么意思”优先词库。
- 复杂知识问答仍走 RAG/后脑工具链。

## 8. 测试建议

至少覆盖以下场景：

1. 常加载词条可直接命中。
2. 懒加载词条首次查询触发加载并命中。
3. 非法行/注释/空行可正确忽略。
4. 重复词条覆盖规则符合预期。
5. `search()` 能返回 term/meaning 匹配结果并受 `limit` 限制。

## 9. 后续扩展

- 增加别名支持（同义词映射）。
- 支持多语言词库分层（如 `zh`, `en`）。
- 增加热重载（文件变更自动刷新）。
