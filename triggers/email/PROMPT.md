# Email Trigger - Fast 模型过滤规则说明

这个文件说明：`EmailTrigger` 在收到新邮件后，如何使用 **fast 模型** 进行“是否提醒 Nora”的快速判定。

实际提示词模板位于：`brain/templates/trigger_email.jinja`。

## 判定目标

fast 模型只做二分类：

- `NOTIFY`：应通知 Nora（后续走自动消息链路）
- `SKIP`：无需提醒，静默忽略

## 输入信息（给 fast 模型）

- 发件人（from）
- 主题（subject）
- 接收时间（date）
- 正文摘要（body_preview）

## 输出契约（必须遵守）

模型必须输出 JSON 对象，且键名保持不变：

- `decision`: `NOTIFY` 或 `SKIP`
- `reason`: 一句话理由

> 若输出格式不稳定，会影响 `EmailTrigger._parse_filter_decision()` 的解析结果。

## 正式过滤规则（建议默认启用）

### A. 必须 `NOTIFY`（高优先级）

满足任一条即可提醒：

1. **安全与账户风险**
	- 登录告警、异地登录、密码修改、设备变更
	- 支付风控、可疑交易、账号封禁/冻结风险
2. **一次性验证码/确认码**
	- 主题或正文明确出现验证码、OTP、2FA、登录确认
	- 且具有明显时效性（通常几分钟内失效）
3. **时效性日程变更**
	- 会议改期、航班/火车/酒店变更、面试时间调整
	- 24 小时内需要处理的安排
4. **财务与账单风险**
	- 扣款失败、逾期提醒、退款异常、续费失败
	- 可能造成损失或中断服务
5. **关键联系人 / 关键项目**
	- 来自明确的关键联系人、上级、核心协作方
	- 或与当前重要事项直接相关并要求尽快响应

### B. 默认 `SKIP`（低优先级）

满足任一条可直接忽略：

1. **广告营销类**
	- 电商促销、折扣、优惠券、活动拉新、品牌推广
2. **批量订阅内容**
	- 新闻简报、周报/月报、资讯推送、内容推荐
3. **社交平台常规通知**
	- 点赞、关注、普通互动提醒（非安全告警）
4. **可延后处理的信息**
	- 无明确截止时间、无风险、无行动要求的普通通知

### C. 条件判断（边界场景）

以下情况需结合上下文判断：

1. **“看似营销，但含强时效动作”**
	- 若包含“今日截止/即将失效/需立即确认”且与已有服务强相关，可 `NOTIFY`。
2. **“普通通知，但来自关键联系人”**
	- 若发件人可信且与当前任务链相关，优先 `NOTIFY`。
3. **信息不足时**
	- 无法判断风险或时效时，倾向 `SKIP`（避免打扰）。

### D. 冲突优先级

若同一封邮件同时命中 `NOTIFY` 与 `SKIP` 条件，按下列顺序决策：

1. 安全风险 / 验证码
2. 时效性行程与会议变更
3. 财务与账单风险
4. 关键联系人与关键项目
5. 营销或订阅属性

即：**高风险高时效优先于“像广告”的表象**。

## 可调策略

你可以在 `brain/templates/trigger_email.jinja` 中调整规则，例如：

- 哪些邮件属于高优先级（应提醒）
- 哪些邮件属于低优先级（应跳过）
- 时效性、风险性、关键联系人等判定标准

> 建议只调整“规则描述”，不要改输出字段名（`decision` / `reason`）。
